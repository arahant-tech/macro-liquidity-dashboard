# 실행된 자사주 매입: SEC 현금 지출 관측

## 1. 무엇을 검증했는가

고정된 5개 발행사의 SEC 표준 XBRL에서 **이미 지급된 보통주 자사주 매입 현금**을 API로 수집하고, 회계기간과 공시 근거를 유지할 수 있는지 검증한다. 이 산출물은 수익률 회귀나 미국 주식시장 전체 자사주 매입액 추정이 아니다.

## 2. 스펙

값을 조회하기 전에 아래 패널과 개념을 코드에 고정했다. 대형 발행사를 편의적으로 선정한 패널이며 시장 대표성이나 과거 생존기업 편향의 해소를 주장하지 않는다.

| 발행사 | 티커 | SEC CIK |
|---|---|---|
| Apple | AAPL | 0000320193 |
| Microsoft | MSFT | 0000789019 |
| Alphabet | GOOGL | 0001652044 |
| Meta Platforms | META | 0001326801 |
| Visa | V | 0001403161 |

- 원천: SEC 공식 `companyconcept` API에서 정확한 `us-gaap:PaymentsForRepurchaseOfCommonStock` 개념을 요청한다. Visa의 정상 HTTP 200 응답이 빈 `USD:{}` 또는 `USD:[]`일 때만, 공식 `companyfacts` API에서 **동일 CIK·동일 us-gaap 계정·USD**를 고정 선택한다. HTTP 403, 계정·발행사 불일치, 잘못된 비어 있지 않은 현금 관측, USD 부재에는 이 경로를 사용하지 않는다.
- 관측 단위: 발행사별 USD 현금 지급액. 해당 개념이 없으면 결측으로 둔다. 승인·발표 금액, 순발행, 다른 주식 종류 또는 기업별 사용자 정의 태그로 대신하지 않는다.
- 기간 선택: 가장 최근 회계기간 말일 → 가장 최근 공시일 → 그 공시에서 가장 긴 현재기간의 실제 보고 금액. 보통 연초 누적 또는 연간 기간이며, 동시에 공시된 짧은 기간은 `alternative_current_durations`에 보존한다.
- 주기: 공시된 실제 `period_start`–`period_end` 기간. 분기 누적액을 월마다 반복하거나 전기 누적액과 차감하여 월간 흐름으로 만들지 않는다. 서로 다른 발행사의 회계기간도 합산하지 않는다.
- 근거: 회계 시작일·종료일, 값·USD 단위, `accession`, 양식, `filed_date`, 프레임, 원천 URL, 원문 SHA-256, 실제 수집시각을 보존한다. Visa 보완 경로는 `acquisition_route=companyfacts_same_concept`와 실제 CompanyFacts URL을 기록하고, 최초 빈 CompanyConcept 원문·해시·수집시각도 별도로 보존한다. 개별 개념 응답은 2MB, 회사 전체 공개 사실 응답은 6MB로 제한한다.
- 시간 규율: `known_by = retrieved_at`. 날짜만 있는 공시일을 정확한 발표시각으로 바꾸지 않는다. `original_release_at=null`, `research_eligible=false`다.

가정: 표준 보통주 재매입 현금 지급 개념이 실행된 기업 자사주 매입의 독립 관측을 제공한다. 다만 현금 결제일과 시장에서 실제 주문이 체결된 날은 다를 수 있고, 가속 자사주 매입 계약의 결제도 섞일 수 있다.

SEC는 [개별 회사·개념 API와 공시 후 갱신 방식](https://www.sec.gov/search-filings/edgar-application-programming-interfaces)을 설명한다. 이 커넥터는 순차 요청과 최소 0.5초 간격으로 [공식 초당 10회 한도](https://www.sec.gov/about/developer-resources)를 밑돈다. 기본 User-Agent는 실제 프로젝트의 공개 저장소를 식별하며, 허구의 이메일을 넣지 않는다. `SEC_USER_AGENT`로 실제 운영자 식별 정보를 설정할 수 있다.

## 3. 결과

2026-09-08 18:27 UTC 실제 재검증에서 **5/5 발행사의 실행 현금 관측을 확보했다.** 앞선 HTTP 403은 사용자가 제공한 실제 운영 연락처를 요청 User-Agent에 설정한 뒤 해소됐다. 연락처 자체는 원문·로그·상태·문서에 저장하지 않는다. 이 검증은 임시 수집 경로에서 실행했으며 클라우드 실행 결과는 배포 후 별도로 확인해야 한다.

| 티커 | 현금 지급 USD | 보고된 실제 기간 | 경로 |
|---|---:|---|---|
| AAPL | 62,094,000,000 | 2025-09-28–2026-06-27 | CompanyConcept |
| MSFT | 22,271,000,000 | 2025-07-01–2026-06-30 | CompanyConcept |
| GOOGL | 0 | 2026-01-01–2026-06-30 | CompanyConcept |
| META | 0 | 2026-01-01–2026-06-30 | CompanyConcept |
| V | 11,625,000,000 | 2025-10-01–2026-03-31 | CompanyFacts 동일 계정 |

Visa의 [개별 개념 응답](https://data.sec.gov/api/xbrl/companyconcept/CIK0001403161/us-gaap/PaymentsForRepurchaseOfCommonStock.json)은 HTTP 200이지만 `USD:{}`이며, [공식 CompanyFacts](https://data.sec.gov/api/xbrl/companyfacts/CIK0001403161.json)의 정확히 같은 계정에는 USD 관측 127개가 있었다. 이는 서로 다른 계정을 대체한 것이 아니라 두 공식 API의 수록 범위 차이다. CompanyFacts 원문은 3,564,517 bytes였고, SHA-256은 `df3caf7c5667296569fc3074ce2ff13629c9a555184a06c5ea9925b43e63971d`다. Visa의 SEC 최신 기간은 3월 말로, 발행사 IR의 6월 말 누적 관측보다 오래됐다. 이 시차를 앞당기거나 서로 다른 기간을 섞지 않는다.

구현 검증은 합성 테스트 **24개 통과**다. 실행 금액과 승인 금액의 구분, 누적기간 보존, 공시 개정, 결측·0·음수, 미래 공시 거부, 실제 수집시각, 원문 해시, 변경 이력, 장애 시 마지막 정상값 보존, 403 후 요청 중단을 확인했다. 추가로 빈 USD 배열·객체에 한정한 Visa 동일 계정 경로, 두 원문 보존, 오래된 실제 기간 유지, 다른 계정·발행사 거부, 크기 상한을 검증했다. 이는 계량적 타당성의 증거가 아니다.

| 평가 축 | 이번 산출물의 범위 |
|---|---|
| 축1 내적 타당성 | 수집·기간·공시·개정 기록을 구현하고 합성 테스트. 원 발표시각은 미인증 |
| 축2 구성 타당성 | 이벤트·NFCI 검증 미실행. 5개사 패널을 시장 전체 흐름으로 해석하지 않음 |
| 축3 외적 타당성 | 계수·표준오차·OOS·분위회귀·거래성과 미산출 |
| 축4 연구자 자유도 | 값 조회 전 패널·태그·기간 선택을 고정. 과거 전체 시도 수는 여전히 미상 |

## 4. Kill criteria

측정모형의 여섯 기준은 **미판정**이다. API 거부를 모형 기각이나 검증 성공으로 해석하지 않는다. 4층 전체 흐름의 충족 여부도 여전히 미완료다. 운영 수집에서는 공식 접근 실패를 명시적으로 오류 처리한다.

403이 지속되면 실제 식별 정보가 담긴 `SEC_USER_AGENT`와 허용된 SEC 접근 환경이 필요하다. 접근 거부를 우회하거나 다른 태그·발표 금액을 실행액처럼 넣지 않는다.

## 5. 이 결과가 틀렸다면 왜인가

가장 큰 파손 지점은 패널 대표성 부재, 기업별 회계기간 불일치, 보고 지연, 현금 지급과 시장 체결의 시차, 사용자 정의 태그 누락 및 SEC API 간 수록 범위 차이다. 현재 API의 과거 이력도 개정되어 있으므로 오늘 받은 과거 숫자를 당시 이용 가능한 정보로 사용하면 미래참조가 발생한다. API 수집 성공으로 이러한 한계가 해소되지는 않는다.
