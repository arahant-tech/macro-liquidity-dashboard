# PBoC 공식 월간 공표자료 연결

## 1. 무엇을 검증했는가

중국인민은행(PBoC)의 공식 공개 표에서 중앙은행 총자산·기타예금취급기관 예치금과 사회융자총량(TSF) 스톡·플로우를 자동 발견·수집하고, 원문·관측월·수집시각·단위를 보존할 수 있는지 검증했다. 측정모형의 계수나 투자 성과를 검증한 작업은 아니다.

## 2. 수집 스펙

구현: `model/providers/pboc.py`, 외부 Python 패키지나 API 키 불필요.

`collect(output_root, transport=None, clock=None)`는 공식 [통계자료 인덱스](https://www.pbc.gov.cn/diaochatongjisi/116219/116319/index.html)에서 가장 최근 공표 연도의 링크를 찾는다. 해당 연도에서 통화·은행 통계와 TSF의 현재 HTML 첨부표를 다시 찾는다. 월마다 바뀌는 첨부파일명을 고정하지 않는다. PBoC가 제공하는 **공개 HTML 다운로드 연결**이며, 문서화된 REST/JSON API라고 주장하지 않는다.

| 수집 ID | 원문 계정명 | 단위 | 빈도·층 | 의미 |
|---|---|---|---|---|
| `PBOC_TOTAL_ASSETS` | 总资产 / Total Assets | 100 million CNY | 월간·1층 PBoC | 중앙은행 총자산 |
| `PBOC_DEPOSITS_OTHER_DEPOSITORY_CORPORATIONS` | 其他存款性公司存款 / Deposits of Other Depository Corporations | 100 million CNY | 월간·1층 PBoC | 기타예금취급기관의 중앙은행 예치금 |
| `PBOC_TSF_STOCK` | 社会融资规模存量 / AFRE(stock) | trillion CNY | 월간·1층 은행신용 | 실물경제에 제공된 금융의 잔액 |
| `PBOC_TSF_FLOW` | 社会融资规模增量 / AFRE(flow) | 100 million CNY | 월간·1층 은행신용 | 해당 월 공표된 금융 제공 플로우 |

예치금은 초과지준, 통화발행 또는 준비통화 총액으로 이름을 바꾸지 않는다. TSF 스톡과 플로우는 서로 다른 공식 관측이며, 스톡 차분을 플로우로 대신 쓰지 않는다. TSF는 비은행·정부채권 등을 포함하므로 순수 은행대출 합계로 해석하지 않는다.

원문 bytes는 `output_root/raw/pboc/<SHA256>.html`에 변경 불가능한 내용별 파일로 저장한다. 각 관측에는 해당 원문의 SHA256, 공식 URL, `known_by`, `fetched_at`, 관측월 시작·종료일이 붙는다. `original_release_at=null`, `research_eligible=false`다. 첨부파일명에 포함된 날짜를 원발표 시각으로 간주하지 않는다. 수집시각은 자료를 그때 확보했다는 증거만 제공한다.

수집기는 현재 연도 전체 원문을 보존하고 각 계열의 마지막 공표 월을 반환한다. 아직 발표되지 않은 월의 빈 칸은 0으로 바꾸지 않는다. 원시 스톡 레벨은 보관용이며 정상성 변환 없이 모형 설명변수에 투입하도록 허용한 것이 아니다.

## 4. Kill criteria

모형의 여섯 kill criteria는 이번 연결 작업으로 통과 판정하지 않는다. 수집 오류, 계정·단위 변경, 회계항등식 실패가 발생하면 해당 소스 관측을 반환하지 않고 오류를 보고한다. 호출하는 집계기는 이전 정상 관측을 유지하되 현재 수집 실패와 자료의 경과 기간을 함께 표시해야 한다.

## 5. 가정과 깨지는 곳

가정: 공식 사이트의 최신 연도·분류 링크가 현재 공표표를 가리키며, 수집한 HTML 표의 계정명이 원래 의미를 유지한다. 수집시각을 당시 이용 가능성의 보수적인 시작점으로 삼는다.

깨지는 곳: 사이트 개편, 요청 차단·일시 장애, 새 연도 표의 미공표, 계정·단위·통계 범위 변경, 과거 월 소급 개정에서 자동 수집 또는 해석이 깨질 수 있다. 최신 표는 과거 실시간 빈티지를 복구하지 못한다. 1시간 확인은 월간 통계를 실시간 경제활동 관측으로 바꾸지 않는다. GitHub 실행 환경에서의 접근성과 실제 예약 실행은 배포 파이프라인이 별도로 확인해야 한다.
