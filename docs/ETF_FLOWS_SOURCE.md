# BTC·ETH 현물 ETF 순유입 관측

## 1. 무엇을 검증했는가

공개 게시자가 보고하는 미국 BTC·ETH 현물 ETF의 일별 순유입을 원문·대상 펀드·영업일과 함께 자동 수집하고, 불완전한 당일 자료를 완성된 흐름으로 오인하지 않는지 검증했다.

## 2. 스펙

원천은 Farside Investors의 [BTC 일별 흐름 표](https://farside.co.uk/btc/)와 [ETH 일별 흐름 표](https://farside.co.uk/eth/)다. 정상 HTTP 요청으로 공개 HTML을 읽는다. JSON API라고 표현하지 않으며, 접근 거부 시 우회하지 않는다.

방법 식별자는 `publisher_reported_net_flow`다. **게시자가 보고한 순유입 관측**이며 발행사의 결제현금을 독립적으로 인증한 자료라는 주장은 하지 않는다. AUM 변화, 투자수익률, 가격 변화 또는 자체 NAV 계산으로 흐름을 추정하지 않는다.

| 구분 | 고정한 게시자 열 범위 | 단위 |
|---|---|---|
| BTC | IBIT, FBTC, BITB, ARKB, BTCO, EZBC, BRRR, HODL, BTCW, MSBT, GBTC, BTC | million USD |
| ETH | ETHA, ETHB, FETH, ETHW, TETH, ETHV, QETH, EZET, ETHE, ETH | million USD |

값 조회 전 다음 선택 규칙을 선언했고, 게시 헤더의 실제 펀드 식별자를 확인한 뒤 코드에 고정했다.

1. 뉴욕의 **현재 날짜는 모두 제외**한다. 행이 숫자로 채워져 있어도 잠정 집계일 수 있으므로 보수적인 보고 지연을 감수한다.
2. 과거 날짜 중 모든 대상 펀드와 총계가 숫자로 채워진 최신 행만 선택한다. 빈칸·대시는 결측이며 명시적 `0.0`과 다르다. 괄호로 표시한 음수는 순유출이다.
3. 같은 날짜의 모든 펀드 합계와 게시 총계가 일치해야 한다. 각 수치가 소수 첫째 자리에서 반올림될 수 있으므로 허용오차를 `0.05 × (펀드 수 + 1)` million USD로 사전 고정했다.
4. 더 최근의 불완전하거나 불일치한 날짜를 제외했으면 사유와 `partial` 상태를 기록한다. 펀드 열이 바뀌면 기존 관측 정의가 조용히 달라지지 않도록 오류 처리한다.
5. BTC와 ETH를 각각 5층·크립토 트랙의 별도 흐름으로 보존한다. 두 자산을 합친 글로벌 유동성 점수를 만들지 않는다.

`period_start = period_end = 게시 영업일`, `known_by = 실제 UTC 수집시각`이다. 원 발표시각은 미확인으로 남기며, 현재 자료를 과거 시점에 알았다고 가정하지 않는다. 연구 입력 자격은 기본 `false`다.

수집 응답의 전체 SHA-256과 **흐름 표 부분의 정확한 HTML 원문 및 해시**를 남긴다. 페이지 하단에 요청 IP가 표시될 수 있으므로 전체 웹페이지 본문을 보관·공개하지 않고 흐름 표 부분만 저장한다. 매번 원문 캡처를 별도로 보존하고, 같은 날짜·값은 최초 `known_by`를 유지한다. 개정은 새 이력으로 추가한다.

## 4. Kill criteria

측정모형의 여섯 기준은 **미판정**이다. 두 데이터 원천의 수집 성공은 잠재 유동성 모형의 채택 근거가 아니다. 기존 주식 ETF 순유입, 시장 전체 자사주 매입, 채굴자 매도압 등 다른 미확보 항목도 해결됐다고 표시하지 않는다.

## 5. 가정과 깨지는 지점

가정은 게시자의 순유입 표가 명시된 펀드 집합에 대해 일관된 흐름을 제공한다는 것이다. 게시자의 기초 계산 방법과 발행사 결제자료를 독립 대조하지 않았으므로 보고 오류·추정 오차·개정이 남는다. 펀드 출시나 명칭 변경, HTML 구조 변화, 접근 제한, 더 최근 행의 결측에서 수집이 깨질 수 있다. 완전한 이전 날짜를 선택하는 규칙도 실시간 시장 내 흐름을 포착하지는 못한다. 따라서 이 데이터로 방향을 예측하려면 미래 흐름 자체에 관한 별도 예측 문제가 남는다.
