# 채굴자 매도 활동: 직접 공시 관측

## 1. 무엇을 검증하는가

CleanSpark와 MARA의 공식 공시에서 실제로 매도했다고 보고한 BTC 수량을 읽을 수 있는지 검증한다. 생산량·보유량 차이를 매도량으로 대체하지 않는다.

## 2. 명세

고정 관측 패널은 CLSK·MARA 2개사다. 글로벌 채굴자 모집단을 대표한다고 가정하지 않는다. CLSK는 자체 IR 페이지가 사용하는 공개 뉴스 API에서 가장 최근 운영 보고서를 자동 발견한다. MARA는 자체 IR 홈의 최신 HTML 재무 공시를 따라간다. 두 원천 모두 키가 필요 없으며 로그인·접근 제한을 우회하지 않는다.

CLSK는 해당 월의 `Bitcoin sold` 행들을 직접 읽는다. 현물 매도와 콜 행사에 따른 인도는 구성요소로 별도 보존한다. 합계는 같은 기업·같은 월에 공시된 매도 항목만 더한 것이다. MARA는 명시적인 `we sold ... bitcoin` 문장과 명시된 3/6/9/12개월 기간을 함께 읽는다. 직접 분기 값이 있으면 채택하고, 없으면 공시한 YTD를 그대로 유지한다. 두 YTD의 차분이나 월별 반복을 만들지 않는다.

전용 `track=crypto`, `layer=5`, `role=flow` 원자료다. 양수는 보고된 매도 수량이다. `known_by`는 실제 확보시각이며 발표 순간이 아니다. 문서 원문·SHA256·기간·공시 출처를 보존한다. 누락·미래 날짜·불명확한 값·새 매도 항목·중복 충돌은 실패 처리한다. 다른 채굴사의 실패는 정상 자료를 지우지 않는다.

## 3. 결과와 검증

로컬 실제 수집에서 두 원천 모두 성공했다. 공개 서버의 결과는 `live-data.json` 상태가 기준이다. 단위는 공시 기간 동안의 BTC이며 기간이 다른 기업끼리 합산하지 않는다. 월간·YTD 원기간, 0/결측 구별, 콜 행사 인도 포함, 선언/생산/잔액과 매도 구분, 미래·충돌 차단, 원문 해시, 부분 실패를 합성 테스트로 검증한다.

## 4. Kill criteria

연결 성공은 채굴 매도가 가격의 하방 꼬리를 설명한다는 검증이 아니다. 계수·4축 타당성·kill criteria는 미평가다. 봉인 연구 표본은 갱신하지 않는다.

## 5. 가정과 깨지는 곳

가정: 기업이 매도 수량과 해당 기간을 정확히 보고한다. 새 공시의 계정명·기간 구조가 파서 계약과 일치한다.

깨지는 곳: 공시 지연·비감사 수치·개정·HTML 변경·자료 누락이 발생할 수 있다. 매도 물량에는 과거 보유·구매한 BTC가 포함될 수 있다. 실현된 과거 매도와 현재 거래소 매도압은 다르다. 대차·담보 이전·해시레이트로 이 빈틈을 채우지 않는다. 이 자료는 2개사의 지연된 매도 활동 관측이며 전체 온체인 채굴자 매도압 지수로 표시하지 않는다.
